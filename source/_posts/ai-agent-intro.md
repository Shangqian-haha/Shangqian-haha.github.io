如果说 2023 年是大模型的元年，2024 年就是 **AI Agent 的元年**。

这一年里冒出来一堆名词：AutoGPT、LangGraph、Manus、Devin……背后都是同一个东西——**让大模型从"回答问题"进化到"完成任务"**。

这篇笔记把上课讲的 AI Agent 概念拆开讲，零基础也能看懂。

## 一、Agent 到底是什么？

课件上给了两个领域对 Agent 的定义，都很学术。我翻译成大白话：

- **计算机领域**：一个能代表你、**自动**干活的软件（不需要你一直戳它）
- **AI 领域**：一个能**感知环境、做决策、执行动作**的智能系统

**两者的共同点**：自主、持续、不需要人一步步指挥。

> 举个生活例子：扫地机器人
> - 感知：看到桌脚、红外测距
> - 规划：决定走 S 形还是贴边
> - 行动：启动轮子、打开吸尘
> - 观察：电量低了 → 回充电桩
>
> 全程没让你指挥。这就是"Agent"——有自主目标，能自我调整。

## 二、大模型为什么不能直接当 Agent？

理论上 GPT-4 已经很强了，但课件列了三条它做不到的事：

- ✕ **不能像人一样规划思考**（不会主动拆任务）
- ✕ **不会用工具**（不能自己查日历、发邮件、跑代码）
- ✕ **没有持久记忆**（聊完就忘，下次又是陌生人）

所以课件给了个公式：

> **AI Agent = LLM + 记忆 + 工具 + 规划**

LLM 负责"思考"，但单独一个 LLM 啥也干不了。给它加上记忆、工具、规划能力，它才能真正"办事"。

## 三、传统 LLM vs AI Agent

| 维度 | 传统 LLM | AI Agent |
|---|---|---|
| 交互模式 | 一问一答 | 目标驱动 |
| 任务复杂度 | 单步简单 | 多步复杂 |
| 工具使用 | 无 | 能调 API / 搜索 / 跑代码 |
| 记忆 | 没 | 短期 + 长期 |
| 自主性 | 你问它答 | 给目标自己跑 |

**一句话总结**：传统大模型是"你问它答"，AI Agent 是"你给目标它自己搞定"。

## 四、四大基础组件

AI Agent 的"四件套"：

| 组件 | 别名 | 类比人 | 干啥 |
|---|---|---|---|
| **LLM** | 大脑 | 大脑 | 理解、推理、生成 |
| **Memory** | 海马体 | 海马体 | 短期+长期记忆 |
| **Tools** | 双手 | 双手 | 调外部 API/服务 |
| **Planning** | 思维 | 思维 | 拆任务、反思改进 |

四者协作的流程：

> 接收任务 → LLM 理解 → Planning 拆解子任务 → 调 Tools 执行 → Memory 记录 → 观察结果 → 反思改进 → 交付

这就是 Agent 的"完整工作流"。

## 五、决策闭环：感知-规划-行动-观察

课件上画了张图特别清楚，我用智能家居的场景展开：

> 用户说："我觉得有点冷"
>
> 1. **感知**（Perception）：识别用户意图 = 想升温
> 2. **规划**（Planning）：决定调高温度到 23°C
> 3. **行动**（Action）：执行调温指令
> 4. **观察**（Observation）：传感器反馈当前 23°C
>
> 用户再反馈："还不够暖"
>
> → 回到规划 → 调到 25°C → 观察 → 用户满意 → 结束

**关键点**：这是一个**持续循环**，不是一次执行完就拉倒。

## 六、两大核心能力

### 1. 任务拆解（Task Decomposition）

把大任务拆成可控的子任务。

比如"写一篇 AI Agent 报告"：
- 收集资料
- 整理大纲
- 撰写正文
- 校对润色

Agent 接到任务，自己拆、自己排序、自己完成。

进阶玩法：**Tree of Thoughts（思维树）**。不是一条路走到底，而是在每一步生成多个分支，**评估+搜索**选最优解。适合那种"答案不唯一、需要探索"的问题（比如 24 点、迷宫）。

### 2. 反思改进（Reflection）

Agent 不是一错就完蛋，它能**复盘自己的行为**、从错误里学。

课件上提到了 **ReAct 框架**（Reasoning + Acting）：

```
Thought:  分析当前状态
Action:   执行具体操作
Observation: 观察执行结果
→ 重复循环
```

每一步都先想再干，错了就调整。**这就是"三思而后行"的算法版**。

## 七、Plan-and-Execute 模式

ReAct 是"边想边做"，还有一种叫 **Plan-and-Execute** ——"先想好再动手"。

适用场景对比：

| 模式 | 思路 | 适合 |
|---|---|---|
| ReAct | 边想边做，灵活调整 | 探索性、动态任务 |
| Plan-and-Execute | 先列全计划，再逐步执行 | 流程明确、可预见 |

> 写代码、写周报、数据分析这些**结构化任务**用 Plan-and-Execute 更稳。
> 调试 bug、找资料这些**需要摸索的任务**用 ReAct 更灵活。

## 八、五大开发框架对比

课件上给了张表：

| 框架 | 代理模式 | 核心特点 | 适合场景 |
|---|---|---|---|
| **LangChain** | 单代理 | 模块化、生态丰富 | 通用开发 |
| **LangGraph** | 状态流 | 有向图，循环分支控制 | 复杂决策流程 |
| **Semantic Kernel** | 单代理 | 微软生态、插件化 | 企业 .NET / Azure |
| **AutoGen** | 多代理 | 多角色对话协商 | 多 Agent 协同研究 |
| **CrewAI** | 多代理 | 角色分工、流程可视化 | 团队协作模拟 |

**选型建议**：
- 做单 Agent、想生态最全 → **LangChain**（或 LangGraph，要复杂流程时）
- 做多 Agent 协同研究 → **AutoGen**
- 在 .NET 体系下 → **Semantic Kernel**
- 想直观地"管一群虚拟员工" → **CrewAI**

我目前主要用 LangChain + LangGraph，生态资料最多。

## 十、为什么 Agent 是"革命"

老师讲课时反复强调一句话：

> AI Agent 让 AI 从"回答问题"进化为"完成任务"。

这不光是技术升级，是**人机关系的根本变化**：
- 以前：你得会"问"，才得到好答案
- 现在：你只要会"布置任务"，让 AI 自己想办法

**它不会取代你，但它会放大你和不会用 Agent 的人之间的差距**。

## 写在最后

学完 Agent 这节课，最大的感触：**别再把大模型当"聊天机器人"用了**。它是一个能调工具、能记东西、能拆任务的"半自主助理"。学会给它布置任务，比学会写提示词还更省事。
