很多人对数据分析有误解，我一开始也是。

以为数据分析就是"会写 SQL 把数取出来"，再高级点就是"用 Python 跑个机器学习"。直到上了这堂课才发现：**数据分析的重心根本不在工具，而在业务**。

这篇笔记把我对"数据分析"这件事的认知掰正过程记下来。

## 一、数据分析到底是个啥

课件给的定义挺正式：

> 数据分析是结合多学科知识，通过**收集、清洗、转换、建模和解释**数据，提取价值信息、洞察规律并支持决策的过程。

我翻译成人话：**就是"从一堆乱七八糟的数据里，找出有用的结论，帮老板做决定"**。

它的四个核心目标，也是数据分析的四个层次：

| 目标 | 回答什么问题 | 大白话 |
|---|---|---|
| **描述现状** | 发生了什么？ | 这月卖了多少钱、涨了还是跌了 |
| **诊断原因** | 为什么发生？ | 为啥这月跌了？因为网红带货没起来 |
| **预测趋势** | 未来会发生什么？ | 下季度大概能卖多少 |
| **优化决策** | 应该怎么做？ | 该砍掉哪个渠道、投哪个网红 |

一句话记住：**描述 → 诊断 → 预测 → 决策**，从易到难，价值也从低到高。

## 二、一个真实案例：森马网红带货

课件用森马公司举了个特别接地气的例子，我原样搬过来，因为它把"数据分析能干啥"讲透了。

**背景**：森马是国内服装公司，网红带货是它重要的营销手段。过去三年网红带货 GMV（成交总额）一直涨，但**今年放缓了**，公司有点慌。

**痛点**：
1. 要找到"网红带货营销额放缓"的**原因**
2. 要明确能行动的 OKR 和关键目标
3. 还想用数据**挖掘新的海外网红资源**，扩大渠道

你看，公司要的不是"给我拉个销售表"，而是**"帮我搞清楚为什么卖不动了，再告诉我该怎么办"**。

这就是数据分析师的活：不是交一张表，是交一个**带结论、带建议的分析**。

## 三、工作内容长啥样

课件上把工作内容拆成三步：

1. **收集数据**（针对具体业务，把需要的数据抓全）
2. **数据处理与分析**（清洗、转换、建模、解释，提取价值）
3. **出结论给建议**（最终目的是**提高商业利润**）

> 划重点：**第三步才是核心**。前两步是手段，最后"出结论给建议"才是数据分析师存在的意义。光会取数、不会给结论，那叫"取数工具人"。

## 四、技能要求：业务才是大头

这是这堂课最颠覆我认知的一张图。数据分析师的技能配比：

| 技能 | 占比 | 说明 |
|---|---|---|
| **业务能力** | **60%** | 懂需求、懂行业、懂痛点 |
| **SQL** | 35% | 大多数场景 SQL 就能解决 |
| **Excel** | 为辅 | 做周报日报、日常数据处理 |
| **Python 算法** | **5%** | 不要过多涉猎机器学习 |

**看到没？业务能力占了 60%，Python 机器学习只占 5%。**

我以前一直以为数据分析 = 学一堆机器学习算法。结果课件直接泼冷水：**"不要过多涉猎机器学习"**。

为啥？因为真实工作里：
- 大部分问题是"这个月为什么降了"，SQL 一查就知道，根本用不到模型
- Excel 够做日常报表
- Python 算法是少数"预测型"场景才用得上

**结论：先把手上的 SQL 和业务吃透，比学一堆花里胡哨的算法实在得多。**

## 五、两个常见误区

### 误区一：把数据分析师当数仓工程师

这俩真不是一回事：

| | 数仓工程师 | 数据分析师 |
|---|---|---|
| 产出 | 可复用的**数据资产**（数据仓库、ETL 脚本、数据字典） | 针对性的**分析报告**（决策建议） |
| 服务对象 | 整个公司的数据应用 | 具体业务问题 |
| 举个产出 | 稳定运行的数仓 | 《网红带货效果分析报告》 |

数仓是"铺路搭桥"，数据分析是"开车送货"。前者建设基础设施，后者直接对业务负责。

### 误区二：数据分析 = 写 Python / 机器学习，或者 = 做 Excel / SQL 取数

这两个是**两个极端**，都不对：

- ❌ "数据分析就是写 Python 搞机器学习调优"——太窄了，把 5% 当成了全部
- ❌ "数据分析就是做 Excel 表格、SQL 取数"——太浅了，把手段当成了目的

**真正的数据分析**：用 SQL/Excel/Python 这些工具，**解决业务问题、给出决策建议**。工具是"术"，业务是"道"。

## 写在最后

这堂课我最大的收获是一句话：

> **深入业务**。

数据分析师的价值不在你会多少工具，而在你**能不能用数据帮业务赚到钱、省下钱**。

给想入门的同学三个建议：
1. **先把 SQL 练到能解决 90% 的取数问题**（这是吃饭的家伙）
2. **再补业务认知**——去了解你所在行业的常识、痛点、指标
3. **机器学习最后再碰**，等前面两样扎实了再学不迟

工具会过时，但"懂业务"这个能力永远值钱。
